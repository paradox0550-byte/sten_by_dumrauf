Дата инвентаризации: 2026-11-04  
Ветка: `fix/backend-manual-release-5-4-1`

Это единый список старых, дублирующих и спорных файлов. Оригиналы пока не удалены: перед удалением нужно убедиться, что не сломаются runtime, сборка, PWA, отдельная функция MarkItDown или восстановление. В разделах ниже указаны конкретные пути и условия.

## 1. Побайтные дубли — кандидаты

| Путь-кандидат | Совпадает с | Что проверить перед удалением |
|---|---|---|
| `api-gateway-spec.yaml` | `api-gateway.yaml` (полностью одинаковый файл) | В репозитории `api-gateway.yaml` назначен единственным каноническим файлом шлюза. Удалить копию после проверки внешних инструкций/ссылок. |
| `src/features/ai-steps/steps.test.ts` | `src/features/ai-steps/steps.test.tsx` (оба файла содержат один импорт `steps.test-cases`) | Оставить один тестовый entrypoint, иначе Vitest может запускать одинаковый набор тестов дважды. После удаления повторить `npm test`. |
| `public/brand/sten-mark-light.svg` | `public/brand/sten-mark-white.svg` | README бренда называет light старым alias white. Удалять только после проверки внешних URL и ссылок. |

## 2. Совпадающие файлы, которые пока НЕЛЬЗЯ удалять

| Файлы | Причина |
|---|---|
| `backend/markitdown/function.py` и `services/markitdown/index.py` | Код одинаковый, но `services/markitdown/server.py` импортирует локальный `index.py`. Это отдельный контейнерный runtime; удаление файла сломает его сборку. Удалять можно только весь старый runtime после подтверждения, что он больше не используется. |
| `public/icon-192.svg`, `public/icon-512.svg`, `public/icons/favicon.svg` | Содержимое одинаковое, но разные URL используются `manifest.json`, `index.html`, service worker и CI-проверками. Это совместимые публичные пути, не мусор. |
| `api-gateway.yaml` и `api-spec.yaml` | Не дубли: первый описывает интеграции Yandex API Gateway, второй — операции Express backend. Оба нужны. |

## 4. Исторические материалы — сначала подтвердить, что сценарий закрыт

- `docs/MIGRATION_CLOUDRU.md` и `docs/cloudru/` — альтернативная/старая платформа.
- `services/markitdown/` — контейнерная версия конвертера; отдельная от Yandex Cloud Function.
- `docs/recovery/` — аварийные инструкции, сохранять до переноса полезных процедур.
- `docs/design/` и старые аудиты в `docs/design-system/` — переносить только актуальные правила и незакрытые дефекты.
- `docs/ai-training/` — материалы оценки/качества STEN AI; не удалять без проверки использования.
- `docs/DUMRAUF_DOMAIN_SETUP.md` — проверить соответствие текущим DNS и доменам.
- `scripts/migrate-db.sh`, `scripts/migrate-storage.sh` — операционные скрипты; не запускать и не удалять без проверки их последствий.

## 5. Файлы, которые остаются активными

Не помещать в корзину:
- `backend/`, `api-spec.yaml`, `api-gateway.yaml`;
- `src/lib/api.ts`, frontend routes/pages, контракты scope/P&L/auth;
- `.github/workflows/ci.yml`;
- `.github/workflows/deploy-frontend.yml` — оставлен только как ручной workflow; автоматический запуск после CI должен быть отключён;
- `package.json`, lock-файлы, Vite/TypeScript config;
- `public/manifest.json`, `public/sw.js` и необходимые PWA assets;
- `docs/BACKEND_ENV_CONTRACT.md`, `docs/DEPLOYMENT_CURRENT.md`, `docs/PRODUCTION_RELEASE_GATE.md`.

**Правило:** сначала убрать автоматические/небезопасные связи, перенести уникальное содержание, проверить все ссылки и пройти CI. Только затем владелец удаляет кандидатов из этой корзины.
