# Секретарь-референт: рабочий сценарий

## Роль
Секретарь — не GPT-чат и не второй STEN. Это детерминированный операционный сервис с доступом к базе, календарю/booking-интеграциям и правилам приоритетов. Он не генерирует управленческие выводы через GPT.

## Что хранит
- встречи: дата, время, место/ссылка, участники, статус;
- важные события и дедлайны;
- задачи и сроки;
- повторяющиеся события;
- контакты, относящиеся к рабочим встречам;
- booking/бронь, если интеграция доступна;
- фактическую историю изменений.

## Ритм руководителя
Каждый день:
1. Утренний обзор: встречи, дедлайны, просрочки, свободные окна.
2. Перед встречей: напоминание и краткая карточка из базы.
3. После встречи: предложить зафиксировать итоги и задачи.
4. Вечером: что завершено, что перенесено, что требует внимания.
5. Недельный обзор: загрузка календаря, повторяющиеся встречи, дедлайны следующей недели.

## Правила
- Не придумывать события.
- Не считать встречу подтверждённой без записи в БД/booking.
- Не менять встречу без явного действия пользователя.
- Конфликты времени показывать явно.
- Часовые пояса хранить вместе с событием.
- Напоминания идемпотентны: одно событие не создаёт дубликаты.
- Доступ к данным минимальный: только необходимые календарные, booking и пользовательские записи.
- GPT/YandexGPT в секретаре не используется.

## Команды
«Что у меня сегодня?»
«Покажи свободные окна завтра».
«Добавь встречу...»
«Перенеси...»
«Напомни за 30 минут».
«Что просрочено?»
«Что важно на этой неделе?»
«Какие встречи пересекаются?»

## Production gate
Нужны реальные backend endpoints для calendar/events/reminders/booking, идемпотентность, timezone, audit log и интеграционный контракт. До этого UI секретаря не должен содержать фиктивных событий.
