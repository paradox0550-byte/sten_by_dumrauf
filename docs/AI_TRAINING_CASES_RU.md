# STEN AI — ручные учебные сценарии

Эти сценарии проверяют фактические ответы API, а не имитируют обучение модели. Для DOC/CALC-сценариев используйте только согласованные тестовые документы без персональных данных и реальных зарплат. Оценку ставит проверяющий после сравнения с первоисточником.

## Подготовка фикстур

Подготовить обезличенный Excel-файл с двумя листами и документированными данными:
- Лист «Команда»: несколько сотрудников, должности и выплаты; максимальная выплата не в первой строке, а ФИО и должность находятся в той же строке.
- Лист «Доплаты»: одна выплата выше максимума с первого листа, чтобы проверить поиск по всем листам.
- Пустые выплаты и текстовые заголовки, которые нельзя считать нулём.
- Отдельный файл мотивации с формулой, порогами, весами и входными значениями, позволяющими рассчитать результат вручную.
- Зафиксировать ожидаемые результаты отдельно от загружаемых файлов; не класть эталон в контекст модели.

## Запуски через «Лабораторию ответов»

1. **GEN-01 — «Привет».** PASS: короткое естественное приветствие, без деловых выдумок.
2. **DOC-01 — максимальная зарплата.** PASS: точный максимум по обоим листам, сотрудник подтверждён строкой-источником, названы файл и лист.
3. **CALC-01 — мотивация.** PASS: найдена формула из файла, показаны входные значения и арифметика; итог совпадает с независимым расчётом.
4. **DOC-02 — первые 10 строк.** PASS: исходный порядок и значения, ровно 10 строк при наличии минимум десяти строк данных.
5. **DOC-03 — доступные документы.** PASS: список получен актуальным инструментом текущего запроса, без документов из истории.
6. **CTX-01 — organization_id / restaurant_id.** PASS: значения приводятся только если доступны из доверенного контекста; иначе явно указано ограничение.
7. **HON-01 — отсутствующий факт.** PASS: модель не подставляет ноль и называет недостающий показатель.

## Протокол оценки

- Запускайте сценарии отдельно и повторяйте минимум три раза после изменения prompt/модели/инструментов.
- Отмечайте PASS только после проверки каждого критерия; «ответ звучит убедительно» не является критерием.
- Для числовых ответов сравнивайте значение, формулу, единицы измерения и источник.
- Если инструменты или файлы не доступны, фиксируйте это как ограничение интеграции, а не как ошибку стиля модели.
- Не отправляйте в benchmark персональные данные, production-зарплаты, токены, секреты и данные другого ресторана.
- Ручные оценки сохраняются локально в браузере. Они не обновляют серверный prompt и не являются fine-tuning.
