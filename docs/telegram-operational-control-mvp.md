# STEN — операционный контроль (MVP)

## Scope

Первый сценарий: «Подготовка ресторана к пику». Это контрольный процесс поверх существующего Telegram Monitor, а не копия чата.

Реализованы доменная модель, сохранение данных, защищённые API, интерфейс в «Мой день» и начальный Telegram-диалог через существующий webhook. Напоминания по срокам и планировщик остаются отдельным этапом. Для ответа бота требуется существующая настройка `TELEGRAM_BOT_TOKEN`; webhook проверяет `TELEGRAM_WEBHOOK_SECRET` и работает только с привязанными групповыми чатами.

## Контрольные точки

1. Раздача и доступность ключевых блюд.
2. Санитария и обязательные журналы.
3. Готовность кассы и команды.
4. Чистота зала и санузлов.

Шаблон — стартовая настройка, а не утверждение, что все рестораны используют одинаковое меню или регламент. Расписание и состав контрольных точек должны настраиваться на уровне ресторана после сверки с действующим регламентом.

## Принципы достоверности

- Ответ сотрудника сохраняется как сообщение сотрудника, а не как независимая проверка.
- При отклонении или запросе помощи требуется описание.
- У каждой задачи есть ресторан, исходное наблюдение, исполнитель и срок.
- Исполнитель может отметить задачу выполненной, но не может подтвердить собственную проверку.
- Просрочка вычисляется по сроку; она не подменяет сохранённый статус задачи.
- Повторное открытие сохраняет причину и историю предыдущего закрытия.
- В MVP нет автоматического рейтинга сотрудников и связи с премированием.
- Этот модуль не меняет P&L и не утверждает, что данные проверены через iiko.

## Состояния задачи

`open → awaiting_verification → verified`

Если срок прошёл, открытая задача отображается как просроченная. Проверяющий может повторно открыть задачу, если проблема сохранилась.

## Следующий интеграционный этап

1. Добавить организационно-ограниченное хранение наблюдений, задач и истории переходов в существующую PostgreSQL-схему.
2. Добавить защищённые API для просмотра контрольных точек, отчётов и действий.
3. Подключить Telegram-кнопки/короткие ответы только после проверки текущего webhook и доступности Telegram Bot API.
4. Добавить напоминания с защитой от повторной отправки и настраиваемой эскалацией.
5. Покрыть интеграционными тестами доступ по организации и ресторану.

## Безопасные границы

Не добавлять миграции вне согласованного механизма схемы, не менять финансовые маршруты, не использовать фиктивные данные, не развёртывать backend автоматически.
