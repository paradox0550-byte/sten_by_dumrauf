# P&L рабочий контур

## Назначение
P&L — не экран просмотра импортированных бюджетов. Это рабочая финансовая таблица управляющего с двумя режимами источника: импорт и ручной ввод.

## Scope
Каждая запись P&L принадлежит period + scope_type + scope_id. Scope должен быть одинаковым для проекта, филиала, ресторана и отдела. Филиал агрегирует только назначенные ему единицы. Самостоятельные единицы вне филиала не сравниваются между собой.

## Таблица
Минимальные колонки:
- Статья
- План ₽
- Факт ₽
- Отклонение ₽
- План %
- Факт %
- Отклонение п.п.
- Статус источника

Статьи не ограничиваются пятью строками. Справочник статей редактируемый, с канонической группой для расчётов и собственным названием пользователя.

## Ручной ввод
Ввод должен быть быстрым:
- 10000, 10 000, 10.000 → 10000
- 10,0 / 10.0 → 10000 при включённом режиме «в тысячах»
- режим масштаба настраивается: ₽ / тыс. ₽ / млн ₽
- формат отображения может быть компактным, но значение в API хранится в базовых рублях
- ввод не превращает пустую ячейку в ноль
- неверное число блокирует сохранение с понятной ошибкой

## План/факт
Для статей, где сравнение допустимо, факт < план подсвечивается как отрицательное отклонение. Цвет применяется к отклонению и/или факту по настройке. Нельзя считать процентное отклонение, если план отсутствует или равен нулю.

## Финансовые показатели
После ввода/импорта backend рассчитывает производные показатели: валовая прибыль, EBITDA, чистая прибыль, food cost %, payroll %, OPEX %, EBITDA margin, net margin. Производные значения имеют формулу и версию.

## Быстрый отчёт
Из P&L открывается отдельное компактное окно:
- выручка план / факт;
- абсолютное и процентное отставание;
- дата/период;
- текущий scope;
- ключевые отрицательные отклонения;
- без неподтверждённых нулей.

## Dashboard
Dashboard использует тот же scope и период. Нужны графики динамики:
- выручка план/факт по периодам;
- EBITDA;
- ключевые расходы;
- отклонение план/факт.
График строится только по подтверждённым точкам; отсутствующие периоды не подменяются нулём.

## Источники
Импорт сохраняет provenance. Ручной ввод также получает source_type=MANUAL и автора/время изменения. Последующее изменение не уничтожает историю аудита.

## Production gate
Нельзя считать P&L готовым, пока backend не поддерживает scope, ручное сохранение, статьи, план/факт, проценты, provenance и историю изменений. Frontend не должен имитировать эти операции локальным state.
